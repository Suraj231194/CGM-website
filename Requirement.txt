Codex-Ready Brief for a Modern Medical Product Website
Laravel + Inertia.js + React + Tailwind CSS + shadcn/ui-style implementation
Executive summary
The website should be built as a modern healthcare product discovery and education platform. It should explain 2 to 3 medical products clearly, build trust, answer common questions, provide patient and clinician resources, capture qualified leads, and redirect users to the main ecommerce website when they decide to buy. This website itself must not implement cart, checkout, payment, subscription billing, or order-management features.
The reference direction comes from Eversense CGM, Omnipod, and Dexcom: all three use benefit-led product storytelling, strong support content, medical disclaimers, patient education, healthcare provider sections, accessibility links, privacy links, and clear get-started paths. The new website should borrow those UX patterns without copying brand assets, copy, layouts, or protected content.
Use the following MVC-oriented stack:
Laravel + Inertia.js + React + Tailwind CSS + shadcn/ui-style components

This gives the project Laravel backend power, React modern UI experience, SPA-like smooth navigation, SEO-friendly server-side routing, and a clean MVC/API structure. The solution should be optimized for content management, product pages, lead forms, support resources, and external purchase redirection.
Updated scope
* Display 2 to 3 products with rich product-detail pages, comparison, FAQs, specifications, safety notes, and download resources.
* Redirect all buying actions to the main ecommerce website using configurable external buy links.
* Implement lead capture, contact forms, demo/request-information forms, newsletter signup, and healthcare provider inquiry forms.
* Include CMS/admin management for pages, products, FAQs, blogs, resources, testimonials, and external buy links.
* Exclude cart, checkout, payment gateway, subscription billing, inventory management, order history, and ecommerce account flows.
Reference pattern analysis
The three reference websites converge on a clear pattern: educate, reassure, compare, support, and convert. The conversion for this project is not an on-site purchase. It is either a lead submission or an external buy redirection.
Reference patternHow to adapt itProduct discoveryUse visually rich product cards, product detail pages, comparison sections, and “Which product is right for me?” guidance.Patient educationAdd learning content, glossary, FAQs, guides, app/setup information, safety information, and downloadable documents.Healthcare provider contentCreate a separate HCP section with product overview, clinical/resources links, request-info form, and disclaimers.Support-first navigationMake Support, FAQ, Contact, Manuals, Compatibility, and Safety Information easy to find from header and footer.Conversion CTAsUse “Learn More”, “Compare Products”, “Request Information”, “Find a Provider”, and “Buy on Main Store” CTAs.
Selected MVC stack
Use Laravel as the MVC backend and application shell, with Inertia.js connecting Laravel routes/controllers to React pages. React will power the premium front-end experience, while Laravel will handle routing, controllers, validation, models, CMS/admin workflows, form submissions, and email notifications.
LayerRecommended choicePurposeBackend / MVCLaravelControllers, routes, services, validation, jobs, policies, models, form handling, and admin workflows.Frontend bridgeInertia.jsConnect Laravel server-side routes with React pages without building a separate API-only SPA.FrontendReact + TypeScriptModern component-driven UI, product comparison, interactive forms, animations, and reusable sections.StylingTailwind CSSFast custom design system with responsive layout, spacing, colors, and typography.UI componentsshadcn/ui-style componentsModern accessible component patterns using Radix-style primitives and Tailwind-based customization.Admin/CMSFilament Admin PanelManage products, pages, FAQs, blogs, forms, resources, redirects, and settings.DatabaseMySQL or PostgreSQLStore products, pages, FAQs, leads, blog posts, resources, redirects, and form submissions.Async jobsLaravel QueuesProcess emails, form notifications, import/export tasks, and background jobs.EmailLaravel Mail + approved email providerSend contact confirmations, lead notifications, and admin alerts.Forms/validationLaravel validation + React Hook Form + ZodStrong server-side and client-side validation for all forms.

Product display and external buying model
This website must not behave like an ecommerce store. It should provide product education and then redirect users to the main ecommerce website for purchasing.
* Each product has one or more admin-configurable external buy URLs.
* Each “Buy on Main Store” click should open an interstitial redirect notice or a clearly labeled external link.
* Track only safe, non-sensitive analytics such as product slug, CTA location, and redirect destination key.
* Do not store payment data, cart data, order data, subscription status, or inventory data in this website.
* Use UTM parameters or redirect IDs when the main ecommerce site requires campaign attribution.
* Provide fallback contact/request-info CTA when a product is not available for online purchase.
